<product_name>
ProjectLens — Mobile-First Read-Only Project Viewer
</product_name>

<core_idea>
Build a beautiful, professional, browser-based, client-side-only project/file viewer.

The user should be able to upload ONE ZIP file containing an entire software project. The application must extract that ZIP entirely in the browser and present the extracted project as a familiar expandable/collapsible file tree, strongly inspired by the usability of VS Code's Explorer sidebar.

When the user selects a file, its contents must be displayed in a large read-only code/document viewer. Programming files should receive high-quality syntax highlighting appropriate to their language. The product is primarily intended for quickly understanding, reviewing, studying, navigating, and inspecting projects without installing VS Code or opening a laptop.

MOBILE IS THE TOP PRIORITY.

The application must feel like a premium developer utility:
- professional
- focused
- minimal
- technical
- calm
- highly usable
- responsive
- fast
- polished
- desktop-capable but designed mobile-first

It must NOT feel:
- childish
- flashy
- overly colorful
- game-like
- gimmicky
- cluttered
- like a generic dashboard
- like an AI-generated template

This is a READ-ONLY application. It is for viewing/studying/exploring project files only.
</core_idea>

<primary_user_problem>
Developers, students, interview candidates, teammates, reviewers, and anyone trying to quickly understand a codebase often have to:
- download/extract a ZIP
- browse many folders manually
- open files one by one
- install/open VS Code on a computer
- deal with unnecessary setup just to inspect a project

This product solves that by making project inspection immediate:

ZIP upload → browser extraction → familiar project tree → tap a file → read its contents.

Zero backend. Zero account. Zero login. Zero setup.
</primary_user_problem>

<hard_constraints>
1. CLIENT-SIDE ONLY.
   All ZIP extraction, directory parsing, file reading, UI state, and rendering must happen in the user's browser.

2. NO BACKEND.
   Do not create an API server, database, authentication system, cloud storage layer, or upload endpoint.

3. NO LOGIN / SIGNUP.
   The user should be able to use the application immediately.

4. NO FILE EDITING.
   Files are strictly read-only.
   No save button.
   No editing mode.
   No content modification.
   No renaming.
   No deleting.
   No creating files/folders.
   No terminal.

5. NO PROJECT MODIFICATION.
   The uploaded ZIP is only inspected locally.

6. MOBILE-FIRST.
   Design and interaction decisions must prioritize phone screens first, then scale beautifully to tablets and desktop.

7. DO NOT REQUIRE VS CODE.
   Recreate the useful exploration experience of a VS Code-style file explorer without pretending to be a full IDE.

8. DO NOT OVERENGINEER.
   Implement features that directly support project inspection. Avoid unnecessary authentication, cloud features, collaboration, AI chat, online storage, social functionality, package installation, execution of uploaded code, or project running.

9. PRESERVE CONTENT.
   For readable text/code files, display the file content exactly as stored in the ZIP, without rewriting, auto-formatting, prettifying, indentation changes, or silent transformations.

10. SECURITY / ISOLATION.
    Never execute uploaded JavaScript, HTML, shell scripts, Python, or other project code. Treat all uploaded files as untrusted data.
</hard_constraints>
